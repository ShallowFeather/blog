    Analysis of Virtualization-based Obfuscation

    Virtual Machine Basics

    假設有此 code 且想要利用虛擬機進行防護

    透過把指令進行轉換可以讓他變成其他種形式，並且有另外的 instruction set

    最後會變成這樣，指令就已經被轉從自定義的 instruction 被轉化為對應的 bytecode 並且也無法正常 decompile

    而 vm_entry 正是一個重要的元件

    💡 Core Comonents - VM Entry/Exit 將程式內容從 native 的內容轉化為 virtual 的內容 - VM Dispatcher 轉發器，進行解碼，執行以及循環 - Handler Table instruction 指令表

    VM Entry / Exit

    • Entry 會將 native 的內容(Register, flags) 輸入 VM 的內容中
    • Exit 則是將 VM 的內容還原回 native

    Native Register 跟 Virtual Register 通常是 1:1

    VM Dispatcher

    1. 獲取指令並且解碼
    2. 把虛擬機的 rip (vip) 往前
    3. 查看 opcode 對應的 Handler Table
    4. 呼叫 Handler Table 對應的指令

    Handler Table

    • Opcode 會透過 Table 指向 Function
    • 每個 Virtual instruction 都有一個 Handler
    • Handler 會解碼指令，並且更新 VM 內容

    虛擬機中的資料結構

    • Bytecode
      • 當中的資料主要是由 bytecode 構成 並且由 vm 去解釋各指令
    • Virtual instruction pointer
      • 指向目前 instruction (bytecode) 的指標
      • 執行完指令後會依照 instruction 的長度增加
      • 基本上就是 rip
    • Virtual Stack Pointer
      • 指向虛擬機中 stack 的頂端 (TOS)
      • 透過 vpush 和 vpop 來更動

    舉例來說

    • RSI 就等同於 Virtual Instruction Pointer
    • RBP 等於 VM Content

    可以看到 dispatcher 在進入 handler_table 前對 RSI++

    並且 vnor 中將參數從 rbp 中拿出來，並且在最後把資料再次丟回 rbp 中

    Register-Machine Machine

    • 會將參數放在 virtual register 中
    • 把結果存在 virtual register 中

    舉例來說：

    x = x + y + 1

    mov rax, x
mov rbx, y
add rax, rbx
inc rax

    Stack-Based Machine

    • 從 stack 中 pop 參數
    • push 結果到 stack 中
    push x
push y
add
push 1
add

    這樣 stack 在執行時主要是把參數放到 stack 上，並對 stack 的參數進行操作

    破解虛擬殼

    • 定位 VM 的 Bytecode
    • 了解 VM 的架構以及內容
    • 逆向出他的 handler table
    • 重新架構 VM 控制流
    • 重新架構高層次的控制流

    目標

    要更加了解 VM 的話

    • 確認 VM 基本的元件以及架構
    • 偵測 handler 的特徵
    • 還原 handler 邏輯

    Lab 1

    這邊的話我是用 IDA 來進行分析

    首先分發器可以看最終分支的流向 loc_1207 來判定是這個地址，但是 graph 的話不太直觀，因為分成很多 block 所以開啟 text mode 可以直接看到

    基本上會是 到他有出現 jmp loc_1207 之前的最後一個 jump，因為最後會跳回分發器起點

    而 Bytecode 則是會在 0x4060 的位置，因爲他透過 rdx 作為 vip 來對 bytecode 進行解碼

    基本上只要經過 decompile 以後再將指向 vip 的變數命名為 opcode 就能夠判斷他指令的對應了。 可以判斷出 rcx 其實就是 stack top pointer

    opcode 是 0xD5

    這可以判斷出 他將 vip 指向的 bytecode 除去 opcode 後的 4byte 丟到 eax 中，vip+=5

    並且將 eax 塞到目前參數當中並讓 rcx 指向那邊，也就是執行 push rdx 除去 opcode 的4 byte 到 stack 頂端

    opcode 是 0x66

    他這個 handler 沒有輸入參數，可以看到直接將 vip + 1

    然後將 stack 頂端的值取出並讓 stack 頂端的下一個值加上剛剛取出的值 最後把 stack pointer - 8 因為少掉了原本的那個值

    等於 stack[1] += stack[0] , pop

    opcode 是 0xf1

    這次圖比較大

    可以看到他檢查 stack 頂端是否為 0

    如果是 0 就跳到 1298 如果不是就繼續執行

    如果是 0 就直接讓 vip + 5 也就是 opcode + 4byte

    如果不是 0 就把 vip + 1 也就是 opcode 除外的 4 byte 賦予給 rax 並讓 vip 指向 vip + rax + 1

    等於是做 基於 輸入參數 的跳躍 就是跳到 vip + rax + 1 並且由 stack 頂端決定是否跳躍

    最後 pop stack

    也就是做了 conditional branch

    符號執行

    • 會將 assmebly 變成代數運行
    • 提供指令，基本區塊以及路徑的符號狀態

    → 支援自訂的虛擬機分析

    • 可以填入具體值，（動態 or 動態和符號結合）
    • 動態 VM 反組譯

    舉例來說，他會將 assembly 轉換為右邊的形式

    他給的程式碼可以看到他執行 basic block register 的變化 可以看到像是 vip + 0x5 之類的

    這邊沒什麼重點xD

    自製符號執行 Disassembler

    流程

    1. 製作一個符號執行引擎會自動跟蹤執行流並且每經過一個 block 就暫停一次
    2. 在 vm Entry 開啟 引擎
    3. 當每次停止時，去檢查他 register/memory 的變化
    4. 分析該 block 並且分析完後讓他跑到時會輸出這會做什麼 並將 block 填入白名單中
    5. 當 SE 觸發 VMexit 就嘗試去重建控制流

    Basic block

    程式區塊他的辨別條件主要是是否有跳到其他位置為一個 block

    並且 block 可能會有出現分支，也就是 next block 在滿足某一條件會跳到不同位置

    這邊其實可以透過分析他給的code來自己讀

    主要是要先辨識出哪些是 handlers 判斷出來後就可以將該 basic block 丟入 disassemble 中

    由於我們已經知道各handlers 在幹嘛就能夠自己判斷該填什麼指令進去
